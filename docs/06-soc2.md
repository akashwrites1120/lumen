## 1. Trust Service Criteria Mapping

SOC 2 Type I evaluates the *design* of controls at a point in time. Lumen's
current posture against the applicable Trust Service Criteria (TSC):

### Security (CC6.1–CC6.8, CC7.1–CC7.5)
| Control area | Status | Evidence |
|---|---|---|
| Encryption in transit (TLS 1.2+) | ✅ | API + web served over TLS; Fastify behind reverse proxy |
| Encryption at rest (AES-256) | ✅ | Storage drivers support server-side encryption; S3 KMS |
| Access control / RBAC | ✅ | Org-scoped sessions, role gates on review/export routes |
| Audit logging | ✅ | `audit_events` table, append-only, every AI + human action |
| Vulnerability management | 🟨 | ClamAV scan hook on upload; dependency scanning (Dependabot) pending |
| Penetration testing | ⬜ | Planned for Phase 3 close |

### Availability (A1.1–A1.3)
| Control area | Status | Evidence |
|---|---|---|
| Uptime monitoring | 🟨 | Queue health endpoint (`/v1/queue/health`); external monitor TBD |
| Incident response | ⬜ | Runbook TBD |
| Backup & recovery | 🟨 | DB backups via managed Postgres; storage is durable (S3/local disk) |

### Processing Integrity (PI1.1–PI1.5)
| Control area | Status | Evidence |
|---|---|---|
| Input validation | ✅ | Zod schemas on every route; shared with frontend |
| Pipeline correctness | ✅ | IR → draft → review → export state machine; no export without human approval |
| Quality assurance | ✅ | Spot-check sampling (Phase 3); validator gate on every export |

### Confidentiality (C1.1–C1.2)

|---|---|---|

### Privacy (P1.1–P7.3)
| Control area | Status | Evidence |
|---|---|---|

## 5. Compliance Reports as Audit Evidence

The signed compliance report (`GET /v1/exports/:id/report`) is designed to
double as audit evidence:

- **HMAC-SHA256 signed** (`REPORT_SIGNING_KEY`) — proves the report was issued
  by this Lumen tenant and was not modified after the fact.
- **Includes**: project metadata, export formats + status, review decision
  histogram, validator outcomes, applicable standards.
- **VPAT summary** (`GET /v1/exports/:id/vpat`) — a human-readable WCAG 2.1
  AA criterion-level conformance table for enterprise buyers.

Both endpoints are in the OpenAPI spec and covered by the audit log.
